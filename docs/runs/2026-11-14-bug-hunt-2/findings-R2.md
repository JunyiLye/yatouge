# 第二次深度檢查 R2：賽道、彎道提示、線上協定、簽章（yatouge.html 1225–2578，main c756e2f）

## R2-1（中）房間成員名單由各人自己宣稱，第三者可讓已離開的玩家一直「在場」
- 位置：`makeSupabaseRoom` 的 presence 同步（5115–5120，`sc.roster` 直接來自 `presenceState()` 的 key）與 `rebuild`（5108–5113）；頻道以用戶端自選的 presence key 開啟（5088）。
- 原因：B2 為所有 broadcast 簽章，但名單本身沒有驗證。攻擊者可用另一位玩家的代號當 presence key 加入房間頻道並 `track()`。名單中的 id 其最後驗證過的狀態永遠不會過期，離開訊息也只清 `seen`。
- 影響：主機一直鎖定一個幽靈對手（常是「準備」），不會回到等待、不會重新廣告；新客人加入時因 `v.opp` 仍「在場」而被判滿；比賽中不會顯示對手離開；攻擊者也能藉此釘住任意 id，削弱收件匣的擠出保護。
- 重現（node，真正的 `makeSupabaseRoom` 加假 SDK）：有攻擊者時，客人離開 6 秒後主機仍看到「ready」；沒有攻擊者時顯示離開。
- 預期：在場與否要依發送者能證明的東西，例如驗證過的離開訊息與一段時間內有沒有驗證過的訊息。
- 信心：程式行為高；真實 Supabase 細節中。

## 檢查過、沒發現問題
六條賽道（含上坡）的幾何、彎道提示的鎖定與 GO 擋、水溝、引擎與變速箱、碰撞與終點後判斷、線上驗證函式、觀戰、房間投票、貓捉老鼠、聊天、協定版本、presence 次數上限、簽章與收件匣的各項邊界。

## 可能是設計問題（不是 bug，不修，留給使用者）
1. 彎道提示一旦出現，會一直顯示到通過那個彎，即使玩家在很前面就停下或倒車。
2. 白狼峠上坡起點離第一個彎很近，側邊提示在 GO 時就出現。
3. 大廳同名房間取代號較小者，第三者能搶同名廣告（任何人本來就能以客人身分加入公開房間，影響有限）。
4. presence `track()` 只重試一次，兩次都失敗時該玩家在對方名單中看不見，直到重新訂閱（第 3 批的既定取捨）。
5. 時鐘相差超過 10 分鐘的玩家看不到彼此的第一則訊息（B2 已知限制）。
