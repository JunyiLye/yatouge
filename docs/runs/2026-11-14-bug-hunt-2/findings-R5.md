# 第二次深度檢查 R5：線上執行、主迴圈、操作（yatouge.html 4885–6597，main c756e2f）

結論：一個中、兩個低嚴重度 bug，都不是先前修正造成的退步。`node --test` 697 項通過。

## R5-1（中）同一分頁離開後再加入同一個房間，對方會看到上一場停住的車，可能整場都是（只有 Supabase）
- 位置：`makeSupabaseRoom` 的 `rebuild`（5112）只在對方不在名單且超過 5 秒時清掉 `lows`／`cars`／`seen`；`onBye`（5125）只清 `seen`；`startMatch`（5375）把 `p.n` 從 0 重新開始；`pushSample`（1852）丟掉 n 沒有變大的樣本。
- 影響：主機保留客人上一場的最後車輛樣本（n 很大），客人回來後的新樣本（n = 1、2、3…）全部被當成過期丟掉，主機看到客人的車停在上一場的位置（常在終點後），直到新的 n 超過舊值；約每秒 30，2–3 分鐘的比賽就是整場。觀戰者也一樣。模擬傳輸不受影響。
- 重現（node，真正的傳輸層）：客人送 n=500 後離開，8 秒後同一分頁回來送 n=1..3，主機緩衝區只剩 500。
- 預期：重新加入時車輛緩衝區是乾淨的。信心：傳輸層高；遊戲內影響中高。

## R5-2（低）對手離開後，結果畫面上對手的名字變成預設的「玩家」
- 位置：`resNames`（5648）讀 `pvp.opp.nk`；`oppGone`（5510）把 `opp` 設成 null；`pvpResultTick` 每 250 ms 重繪。
- 預期：保留最後知道的暱稱（貓捉老鼠已用 `ck.oppNk` 這樣做）。信心：高。

## R5-3（低）按住手把扳機時視窗失去焦點，回來後那個扳機失效到再按一次
- 位置：`blur`（6254）清掉 `input.*` 但沒清 `gp.last`；`gamepadTick`（6398）只在值改變時寫入；`chatClose`（6034）有為同樣原因重設 `gp.last`。
- 預期：`blur` 也重設 `gp.last`。信心：中（邏輯確定，Chrome 失焦時是否仍回報按住未驗證）。

## 檢查過、沒發現問題
簽章協定的接線、送出頻率（約每秒 27 則，低於 40）、計時器與監聽器沒有洩漏、所有加入路徑都經過大廳閘門、房間流程（抽籤、種子、變速箱、取消準備）、E2 與 B3 修正、貓捉老鼠、觀戰、聊天、主迴圈、鍵盤手把觸控、縮放、分頁切換。

## 可能是設計問題（不是 bug，不修）
1. 觀戰時音樂鍵沒有作用。
2. 在對戰房間或觀戰時手把 B 鍵沒有作用。
3. 貓捉老鼠回合之間，客人在主機開始的同時取消準備，仍會被拉進下一回合（一般對戰會回到房間）。
4. 大廳和對戰房間一樣有 64 個發送者上限，大廳超過 64 個發送者時新的房間廣告會被丟掉。
5. 選送酒模式時按「線上」會把模式切到比賽並存檔，即使接著取消暱稱視窗。
6. 觀戰時不會呼叫 `updateEngineAudio`，主畫面的怠速引擎聲持續不變。
7. 主機在結果畫面、或貓捉老鼠對手已離開時，大廳把房間顯示為「比賽中」（只能觀戰）。
8. Supabase 整個專案的訊息額度：大廳每個廣告者每秒一則心跳，玩家變多時要留意。
