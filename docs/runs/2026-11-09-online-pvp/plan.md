# 線上 1 對 1 對戰 — 規格與實作計畫

結論：新增線上對戰模式。玩家在主畫面看到目前開著的房間列表，可以開一個房間或加入別人的房間。兩人都按「準備」之後，雙方同步倒數開跑。對戰時沒有 AI 對手，兩台車會互相碰撞。先抵達終點的人獲勝，結果畫面顯示雙方時間。單人模式完全不變。

Pipeline：Frontend Feature SDD — 完整流程。因為要接收其他玩家傳來、不可信任的資料，有安全面，所以不走 Light Path。不需要 API grounding（沒有後端 API）。

## 使用者已確認的決定（2026-11-09）
- 只有登入 claude.ai、屬於使用者組織或被邀請到這個 artifact 的人可以連線對戰。用公開連結開啟、沒有登入的人只能玩單人模式。
- 2 人對戰，沒有 AI 對手。
- 兩台車會互相碰撞（bumping）。
- 用公開的房間列表配對。

## 技術基礎：claude.ai 的 `room` 能力
- `claude.use("room")` 回傳 null 表示這位玩家無法連線，這時隱藏線上功能，只保留單人模式。
- **只用 presence，不用 emit 事件**。每個人都可以設定 presence，不需要額外權限。平台會合併後送出，大約每秒 30 次，每人最多 4 KiB，足夠同步車子狀態。事件主題預設只有 Editor 以上可以送，用 presence 可以避開這個限制。
- **大廳**：主 room，所有開著頁面的人都在裡面。開房的人在自己的 presence 放 `{ lobby: { room, track, open, v } }`。房間列表由所有人的 presence 推導，關閉頁面時會自動消失。
- **對戰房**：`room.join(name)`，名稱為隨機的 `pvp-xxxxxx`。房內每人的 presence 包含：狀態（waiting / ready / countdown / racing / finished）、車型與顏色、賽道（以開房者為準）、車子狀態，以及完賽時間。車子狀態包括位置、方向、速度、角速度、s、lat、甩尾、方向盤、煞車燈，加上傳送端時間戳記與序號。
- **名稱**：宣告 `user: { scopes: ["profile"] }`，用 `user.profiles([by])` 顯示對方名稱，名稱取不到時顯示「對手」。
- 宣告：`capabilities: { room: {}, user: { scopes: ["profile"] } }`。

## 設計
1. **主畫面**：在「開始」旁加一個「線上對戰」按鈕，只有 room 可用時才顯示。按下後進入大廳面板：
   - 列出開著的房間：開房者名稱、賽道、人數 1/2。
   - 「建立房間」按鈕：開房的人選擇賽道（沿用目前選的）。
   - 點選列表中的房間即可加入。滿兩人的房間不能加入，會從列表中消失，或顯示「已滿」。
2. **房間內**：
   - 顯示雙方名稱與狀態，以及「準備」和「離開」按鈕。
   - 兩人都是 ready 時，雙方各自開始 3 秒倒數。以開房者送出的 `go` 序號為準，避免各自觸發不一致。
   - 對方離開時顯示提示，回到房間等待。
3. **對戰中**：
   - 自己的車照常模擬（本地權威）。
   - 對方的車依收到的狀態**插值顯示**，大約延遲 100 ms；斷訊或延遲時用 dead reckoning 外插，最多 0.5 秒。
   - AI 對手不出現，HUD 上的「領先/落後對手」改為與真人對手的距離。
4. **碰撞**：沿用現有的車對車碰撞框（OBB SAT）與衝量計算。對方的車用插值後的姿態與速度當作障礙物，**只套用到自己的車**。雙方各自算自己那一半，網路延遲時可能略有不一致，這是可以接受的已知限制。重疊的推開量只推自己的車。
5. **終點**：完賽時把時間放進 presence。結果畫面顯示勝負（以雙方的完賽時間比較）與差距。對方 60 秒內沒有完賽時，顯示「對手未完賽」。
6. **不可信資料**：
   - 對方送來的每個欄位都要驗證：型別、是否為有限數值、範圍（位置在賽道附近、速度 < 100 m/s 等）。不合法的資料直接丟棄。
   - 名稱只用 `textContent` 顯示，絕不當 HTML。
   - 房間名稱與賽道 id 只接受白名單格式。
   - 對方的完賽時間只用於顯示，不寫入自己的個人最佳。
7. **斷線**：`connected()` 為 false 持續 2 秒以上時顯示「連線中斷」。單人模式不受影響。
8. **測試用的傳輸層抽象**：
   - 網路部分包成一個傳輸介面，正式環境接 `claude.use("room")`。
   - 另寫一個測試用的 mock，以 `BroadcastChannel` 在同一台電腦的兩個分頁之間傳遞，只在網址帶 `?mockroom=1` 時啟用。這讓 Playwright 可以開兩個分頁實際對戰測試。
   - 正式發布版不會自動啟用 mock。

## 任務（每項先寫測試）
1. **純函式區塊 `@netcode`**，含：
   - `validatePeerState`：拒絕 NaN、超出範圍、型別錯誤；
   - `lobbyRooms(peers)`：推導房間列表，排除已滿、過期、格式錯誤的房間；
   - `interpRemote(buffer, now)`：插值，以及最多 0.5 秒的外插；
   - `raceSync(me, other)`：雙方狀態機，處理 ready、go、countdown、racing、finished；
   - `pvpResult(myT, otherT)`：計算勝負與差距。
2. **傳輸層**：room 與 mock 兩種，介面相同。
3. **UI 與遊戲接線**：
   - 大廳、房間面板（中英文都要有）；
   - PvP 模式關掉 AI；
   - 對手車的 mesh（沿用對手車型，可換顏色）；
   - HUD 顯示與對手的距離；
   - 碰撞接進 `carStep`；
   - 結果畫面。
4. **發布**：宣告 capabilities，正式環境必須接上 room。

## Exit Criteria
1. 從專案根目錄執行 `node --test` 全部通過，0 個失敗。任務 1 的測試先紅後綠。
2. 單人模式不變：既有測試全部通過；瀏覽器實測開跑、AI 對手、結果畫面都正常。
3. 在瀏覽器以 `?mockroom=1` 開兩個分頁：
   - A 建立房間，B 的列表看得到並加入；
   - 雙方按準備後同步倒數（雙方開跑時間差 < 0.3 秒）；
   - 雙方都看得到對方的車在移動；
   - 碰撞時自己的車會彈開；
   - 先完賽的一方在結果畫面上顯示勝利，另一方顯示落敗；
   - B 關閉分頁時，A 看到對方離開；
   - console 沒有錯誤。
4. room 不可用（不帶 mock、也不在 claude.ai 裡）時，「線上對戰」按鈕不顯示，單人模式正常。
5. 惡意資料測試：讓 mock 送出 NaN、超大數值、HTML 名稱、錯誤格式的房間名，遊戲不會壞，畫面不會插入 HTML。
6. **真實環境**：發布到 claude.ai 後，必須由使用者和一位同組織的同事實際連線測試。我無法在這個 session 裡代替兩位真人連線，這一項列為使用者驗收。
7. Build / lint：N/A。

## 未解問題與假設
- **碰撞在延遲下不完全一致**：雙方各自模擬，在高延遲下，可能一方看到撞到、另一方沒有。這是使用者選擇碰撞時已知的取捨。
- **同步的時間差**：兩人各自收到 ready 才開始倒數，延遲約 0.1–0.3 秒，所以開跑時間不會完全一致。最終勝負以各自計時的完賽時間比較，延遲可能影響極接近的結果。
- **房間的權威性**：presence 不是權威，任何人都可以宣稱任何狀態。這只是休閒對戰，不做防作弊。
