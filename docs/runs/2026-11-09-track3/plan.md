## 假設（在回覆中告知使用者）
- **方向**：下坡，從左下的起終點出發，往右上跑。這是圖上「下り」箭頭的方向。
- **只取路線形狀**：圖上的文字（スタート、チェックポイント、第N区間）不放進遊戲，賽道名稱自訂為「白狼峠 / Hakuro Pass」。檢查點與分段計時不在本次範圍。
- **比例**：沿用 3 m/px。若全長過長（超過約 8 km）或過短，再調整比例並回報。
- **路寬**：半寬 `HW` 從 5.2 m 提高到 6.2 m，路面約寬 2 m。

## 設計
1. **描線**：
   - 圖中道路是深色粗帶，中間有淺色中心線，背景為白色。
   - 從道路像素做骨架化，取兩個端點之間的路徑。工具可以沿用 `../2026-11-08-add-seiran-track/tools/` 的做法，或改寫。
   - 去掉圖上的紅色標籤與文字，避免描到錯的地方。
   - 平滑後轉成路點。在曲率過大的地方做局部放寬，但半徑下限要配合較寬的路面。
2. **每條賽道各自的路寬**：
   - 目前的 `HW` 是全域常數，碰撞、護欄、水溝、路面 mesh、鏡頭、AI 的 lat 限制、PvP 驗證範圍與測試都會用到。
   - 改為每條賽道各自設定，例如 `TRACKS[id].hw`，預設 5.2。黑鷺山與青嵐峠的數值與行為必須完全不變（既有的雜湊測試必須通過）。
   - 所有用到 `HW` 的地方改成取目前賽道的路寬。純函式要接收路寬參數，或從賽道資料讀取。
3. **賽道資料**：
   - `TRACKS.hakuro`：名稱為中英文雙語，路點內嵌，`hw: 6.2`，對手 `{ car: 'gtr', color: 黑色 }`。
   - 選賽道畫面加第三張卡片，手機寬度不會破版。
   - 個人最佳成績的 key 為 `yatouge-best-hakuro`。
4. **場景**：
   - 遠山、地面、樹與路燈的範圍依新賽道的外接範圍計算，沿用 `buildTrack` 的通用流程。
   - 不加水溝。
5. **PvP**：新賽道 id 加入白名單，選這條賽道開房也能正常對戰。

## Exit Criteria
1. 從專案根目錄執行 `node --test` 全部通過，0 個失敗。新增的測試先紅後綠：
   - 全長在合理範圍；
   - 起點方向正確，而且沒有鏡像；
   - 沒有路段重疊：以新的路寬計算，相隔遠的點距離 ≥ 2·hw + 8；
   - 最小彎道半徑合理；
   - 點距與方向連續；
   - 路寬的設定：既有兩條賽道的 hw 仍是 5.2，新賽道是 6.2；
   - 對手對應到黑色 GT-32；
   - PvP 接受這條賽道。
2. 黑鷺山與青嵐峠的雜湊測試通過，兩條賽道的行為與現在相同。
3. 瀏覽器實測：
   - 第三條賽道可以選、可以開，黑色 GT-32 對手會跑；
   - 碰撞與護欄的位置依新的路寬；
   - 從上方俯視的形狀與原圖一致，而且沒有鏡像；
   - console 沒有錯誤；
   - 手機寬度的選賽道畫面正常。
4. 全部完成後上傳到原本的 artifact 連結。上傳時宣告 room、user 能力（線上對戰需要）。使用者已經指示上傳。
