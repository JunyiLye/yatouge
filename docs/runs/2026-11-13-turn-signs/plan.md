# 彎道提示圖標（2026-11-13）

結論：比賽中，彎道入口前約 3 秒車程，在畫面上半部、轉彎那一側出現街機風的箭頭圖標，用顏色和形狀告訴玩家彎有多大；髮夾彎與 S 彎各有專屬圖標，出現時會發出提示音。設定裡可以關閉，預設開啟。

## 使用者決定（Design Gate）
1. 樣式：螢幕上的告示牌圖標（不做路邊 3D 看板）。
2. 聲音：要。圖標出現時嗶一聲，髮夾彎嗶兩聲；跟著音效音量。
3. 預設開啟，主畫面與遊戲內選單的設定都有開關；關閉時畫面與現在完全相同。
4. 顯示模式：一般比賽、計時賽、線上；**送酒模式不顯示**，觀戰不顯示。
5. **不要文字，只用箭頭圖標**：
   - 一般彎依大小分顏色：小彎綠、中彎黃、大彎紅（箭頭朝轉彎方向）。
   - 髮夾彎：倒 U 形的回轉箭頭，紅色（開口方向依左右）。
   - 左彎接右彎、右彎接左彎（S 彎）：各有自己的圖標，藍色。
   - 連續髮夾彎不另做圖標，每個髮夾彎各自顯示髮夾彎圖標。
6. 本計畫的推定（使用者可推翻）：既然不要文字，倒數距離數字也不顯示，只有圖標。

## 設計
### 彎道判定（純函式，可測試）
- 載入賽道時，依每個點的曲率 `ks`（每 1.5 m 一點）找出曲率超過門檻的連續區段作為一個彎，計算方向、總轉角、最小半徑。
- 分級（門檻暫定，實作時對三條賽道的結果微調，讓分級符合實際開起來的感覺）：
  - 小彎（綠）：總轉角 < 45° 且最小半徑 > 80 m 以外的情況中最緩的一級
  - 中彎（黃）：45°–90°
  - 大彎（紅）：90°–150°，或最小半徑 < 25 m
  - 髮夾彎（紅色回轉）：總轉角 ≥ 150°（與程式現有的髮夾彎定義一致）
- S 彎（藍）：方向相反的兩個彎，前一個的出口到下一個的入口距離很近（暫定 < 40 m），而且兩個都不是髮夾彎時，合成一個 S 彎提示，依第一個彎的方向分「左接右」或「右接左」。其中有髮夾彎時，各自照原本的圖標顯示。
- 只提示需要注意的彎：曲率極小的緩彎不提示（門檻同樣實作時微調）。
- 寫成 `@turn-signs` 區塊的純函式，例如 `cornerList(pts)` → `[{ s0, s1, dir, angle, minR, kind }]`，以及「目前該顯示哪一個」的 `nextSign(list, s, speed)`。

### 顯示
- 出現時機：彎道入口前約 3 秒車程（依目前車速換算距離，最少 60 m）；進入彎道後淡出；同時只顯示一個，上一個消失後才換下一個。
- 位置：畫面上半部，偏向轉彎那一側（右彎在右上、左彎在左上，S 彎依第一個彎的方向）；避開 HUD 的時間／分數區、車內倒後鏡與手機觸控按鈕；手機橫向也要清楚。
- 圖標用內嵌 SVG 繪製，深色底板加有顏色的箭頭；髮夾彎出現時閃一下。
- 無障礙：圖標加上 `aria-label`（例如「右急彎」），不影響畫面上「不要文字」的決定。

### 聲音
- 用現有的 WebAudio 合成提示音（`beep` 或類似），跟音效音量；髮夾彎兩聲。
- 不改任何既有音效（KX-2 時速警示音等維持原樣）。

### 設定
- 新的 localStorage key `yatouge-turn-signs`（`'1'`／`'0'`，缺值視為開）。
- 主畫面設定與遊戲內選單設定各加一個開關，中英文標籤（例如「彎道提示」／「Turn signs」）。

### 啟動順序
- 所有新的執行期狀態都要宣告在第一次 `applyLang()`、`renderPicker()` 等啟動呼叫之前，並加宣告順序的回歸測試（上一個功能曾因此在載入時當機）。

## 不變
- 關閉時畫面與現在完全相同；送酒模式與觀戰不受影響；既有音效、HUD 位置、倒後鏡大小不變。

## Exit Criteria
- `@turn-signs` 純函式的測試先失敗、實作後通過：三條賽道都找得到彎，現有的髮夾彎都被判為髮夾彎，左右方向正確，S 彎合併規則與髮夾彎例外正確，`nextSign` 依距離與車速出現／消失。`node --test` 全部通過。
- 換行只有 LF、沒有 `__lc`、沒有隱形字元，script 可以解析，頁面載入沒有錯誤。
- 驗證者（一個 headless 瀏覽器、一個分頁；線上用模擬傳輸層兩個分頁）：三條賽道各沿著賽道移動車子，在髮夾彎、各級彎與 S 彎前截圖，確認圖標種類、顏色、左右位置正確；送酒模式不出現；關掉開關後不出現；手機橫向與桌機各拍一組；主控台沒有錯誤。
- 截圖與腳本放在本資料夾（不進 git），瀏覽器與 server 用完全部關閉。
- 使用者試玩確認提示的時機與分級手感。

## 第二輪
- 錯誤修正：離開線上對戰時，`buildTrack` 只把 `tsCur` 清成空字串，之後 `tsHide()` 看到 `tsCur` 是空的就提早結束，圖標的 DOM 沒被藏起來，下一場倒數（以及送酒模式）會看到殘留的舊圖標。根本原因是把「隱藏 DOM」的判斷綁在變數上。修法：`tsHide()` 以 DOM 本身（有沒有 `show`）為準，永遠先清 `tsCur`；`buildTrack` 改呼叫 `tsHide()`。新增測試用假的 DOM 元素驗證，並檢查程式裡只有宣告與 `tsHide` 會寫 `tsCur = ''`。
- 使用者決定：S 彎只合併小彎與中彎。兩個相反方向、間距小於 40 m 的彎，只有在兩個都是小彎或中彎時才合成 S 彎；只要其中一個是大彎或髮夾彎，就各自顯示自己的圖標。

## 驗證與審查紀錄
- 瀏覽器驗證（一個 headless 瀏覽器）：三條賽道每個彎都依序出現一次，圖標種類、顏色、左右、aria-label、嗶聲正確，過彎後消失；倒數、結束、結果畫面、送酒、觀戰、關閉開關時都不顯示；重新開始、換賽道、回主畫面會清除；手機橫向與桌機都不壓到 HUD、倒後鏡與觸控按鈕；線上模擬比賽正常；沒有頁面錯誤。
- 第一輪抓到：離開線上比賽後舊圖標殘留，第二輪修正（`tsHide` 永遠以 DOM 狀態為準，`buildTrack` 改呼叫 `tsHide`），重現腳本 `verify2.cjs` 確認不再殘留。
- 驗證腳本中未通過的項目，經人工確認都是腳本誤判：全螢幕圖層被算成重疊、預設語言不同、SwiftShader 的繪圖警告、白狼峠第一個彎在起跑前就已顯示所以掃描沒錄到嗶聲。
- `node --test`：500 個全部通過。獨立 code review：可以合併。小瑕疵（每幀重寫 aria-label、CSS 位置不整齊）依使用者決定在下一輪一併修正。
