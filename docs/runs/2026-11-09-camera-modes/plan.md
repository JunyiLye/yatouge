# 鏡頭模式：近距離追蹤與車內視角（含後照鏡）— 實作計畫

結論：比賽中新增兩種鏡頭，原本的追蹤鏡頭保留，按 C 鍵在三種之間循環切換：
1. 原本的追蹤鏡頭，維持現狀。
2. 近距離追蹤：比原本更貼近車子。
3. 車內視角：鏡頭在駕駛座，上方中央有後照鏡，即時顯示車後的畫面，而且左右反轉。

選擇會被記住。手機沒有鍵盤，所以 HUD 也加一個切換鏡頭的按鈕。

Pipeline：Frontend Feature SDD — Light Path（單一檔案、無 API、無新相依）。

## 使用者需求（2026-11-09 原話）
「make a new camera that are closer to the car and another one is camera inside the car with back mirror, the original one are keeped and can change by clicking c」

**假設**：
- HUD 的切換按鈕是為了手機玩家加的，使用者沒有要求。若不要，可以拿掉。
- 主畫面的環繞鏡頭不受影響。

狀態：在回覆中告知使用者。

## 現況
- `updateCamera(dt)`（約 1092 行起）有兩段：主畫面的環繞鏡頭，以及比賽中的追蹤鏡頭。
- 追蹤鏡頭的方向會往滑行方向偏（`wgt`，上限 25°），距離 `6.4 + spd*0.035`，高度 `2.5 + spd*0.012`，畫面晃動用 `shake`，視角 FOV 隨速度在 64–78 之間變化。
- 車身是 `playerCar.g`（THREE.Group），水溝的下沉與傾斜做在 `placeCars`。
- 車身的實際大小可以參考碰撞框 `CAR_BOX`：hatch 約 2.15 × 0.83，coupe 約 2.25 × 0.87。

## 設計
1. **鏡頭模式**：
   - 模式列表 `CAM_MODES = ['chase', 'near', 'cockpit']`，按 C 鍵（`KeyC`）切換到下一個並循環。
   - HUD 上有一個按鈕，點擊效果相同，有 `aria-label`，中英文都要有。
   - 切換時跳一個簡短提示，例如「鏡頭：近距離」。
   - 選擇存在 `localStorage` 的 `yatouge-cam`（用現有的 `store` 包裝），預設為 `chase`。
   - 倒數與比賽中都可以切換。主畫面的環繞鏡頭不受影響。
   - 主畫面的操作說明加上一行「C：切換鏡頭」，中英文都要有。
2. **原本的追蹤鏡頭（chase）**：程式行為完全不變。
3. **近距離追蹤（near）**：
   - 沿用 chase 的方向與平滑邏輯（往滑行方向偏），只改距離和高度。
   - 距離約 `3.6 + spd*0.02`，高度約 `1.55 + spd*0.006`，注視點約在車前 3 m、高 0.9 m。
   - 數值可以微調，但不能讓鏡頭穿進車身。
4. **車內視角（cockpit）**：
   - 鏡頭放在駕駛座眼睛的位置：車頭前後方向約在車中心往前 0.1 m，左右偏向駕駛側約 0.35 m（右駕），高度約為車身底部 +1.05 m。
   - 位置與方向跟著車身 group 的實際姿態，包括俯仰、側傾和水溝下沉。可以用 `playerCar.g` 的 world matrix 換算。
   - 看向車頭正前方，不往滑行方向偏，這樣甩尾時看得出車頭和行進方向不同。
   - FOV 約 72–80，隨速度變化。畫面晃動減半。
   - 車內模型：從車內看出去，車身的內側面通常不會被畫出來（單面材質）。這一模式下要嘛隱藏整台車，要嘛只留下引擎蓋。
   - 另外加一個簡單的車內框：用 HTML/CSS 疊加或貼在鏡頭上的 mesh 都可以，包含儀表板下緣、A 柱、方向盤上緣的剪影，不能擋住超過畫面下方約 25%。
   - 原本的速度、轉速 HUD 保留。
5. **後照鏡**（只在 cockpit 模式出現）：
   - 第二台相機從車內往後看，位置大約在擋風玻璃上緣中央。
   - 畫面先畫到一個小的 `WebGLRenderTarget`，大約 256×80，可依螢幕調整。
   - 以畫面上方中央的小矩形顯示，有深色外框和圓角，左右反轉，就像真的鏡子。反轉可以用 UV 翻轉，或用一個 overlay 正交場景顯示。
   - 不要用額外的 WebGL context。
   - 對手車在車後右側時，鏡子裡也要出現在右側（因為鏡像），截圖為證。
   - 效能：後照鏡用低解析度，只在 cockpit 模式時渲染，切出時不渲染。Render target 只建立一次，視窗縮放時要處理。
6. 切換賽道、回主畫面、重新開始時，鏡頭模式維持使用者選的那個。從 cockpit 回到主畫面時，車身要重新顯示。

## 任務
1. **純函式區塊** `/* @camera-modes:start */ … /* @camera-modes:end */`，不依賴 THREE、DOM。先寫測試，再實作。
   - `nextCam(mode)` 會循環切換；未知的值回到 `chase`。
   - `camModeFromStore(v)` 對無效值回傳 `chase`。
   - `nearChasePose(car, camH, spd)` 回傳鏡頭位置與注視點。測試相同狀態下，車到鏡頭的距離比 chase 公式短，而且大於車的半長加 1 m（不穿進車身）。
   - `cockpitPose(x, z, h, y, box)` 回傳眼睛位置、前方向量、後照鏡相機的方向。測試：
     - 眼睛位置在車身碰撞框內（換算到車子座標後，`|前後| < 半長`、`|左右| < 半寬`）；
     - 駕駛側正確（右駕，在車子右側）；
     - 前方向量等於 `(sin h, cos h)`；
     - 後照鏡方向與前方的內積約為 −1；
     - h 換成另一個值時結果跟著旋轉。
2. **接進 `updateCamera`、按鍵、按鈕、HUD 提示、後照鏡渲染、cockpit 隱藏車身、車內框**。這些由瀏覽器驗證。

既有的 79 個測試都要維持通過。

## Exit Criteria
1. 從專案根目錄執行 `node --test` 全部通過，0 個失敗。
2. 任務 1 的測試先紅後綠。
3. 瀏覽器實測：
   - 按 C 依序切換 chase、near、cockpit、chase，每次都有提示。三種模式各一張截圖，console 沒有錯誤。
   - HUD 按鈕效果相同。
   - 重新整理後保留上次的模式。
   - near 模式：車子在畫面中明顯比 chase 大，鏡頭沒有穿進車身。
   - cockpit 模式：
     - 看得到路和車內框，看不到從車內穿模的車身。
     - 後照鏡出現在上方中央、左右反轉：在對手位於車後一側時截圖，對照它在鏡中的位置。
     - 甩尾時視角朝車頭方向。
     - 卡進水溝時，畫面跟著下沉、傾斜。
   - 從 cockpit 回到主畫面：車身重新出現，環繞鏡頭正常，沒有後照鏡。
   - 效能：cockpit 模式的 FPS 和 chase 相比不能大幅下降，用 `requestAnimationFrame` 計數粗略比較即可。headless 的 FPS 不準，只要確認沒有每一幀都重建物件。
4. Build / lint：N/A。
