# 觀戰與計時賽模式 — 實作計畫

結論：本計畫包含兩個新功能，在手排變速箱完成之後依序實作，一次只跑一個 builder。

1. **觀戰**：公開的線上比賽開始後，其他人可以從大廳點「觀戰」進入。觀戰者即時看到兩台車，可以切換跟哪一台車或俯視全景，看得到暱稱、差距與結果。參賽者會看到「N 人觀戰中」。claude.ai 與 GitHub Pages 兩邊都支援；私人房間不能觀戰。
2. **計時賽**：每條賽道都可以單獨跑，不放 AI。依「賽道 × 車型」記錄最佳時間，並以半透明的「幽靈車」重播自己的最佳紀錄。同時顯示甩尾分數。

Pipeline：Frontend Feature SDD — Light Path。觀戰涉及網路資料，沿用既有的驗證，不新增外部服務。

## 使用者決定（2026-11-13）
- 觀戰：觀看並可切換視角（推薦方案）。
- 計時賽：最佳時間加幽靈車（推薦方案）。

## A. 計時賽（先做）
1. **入口**：主畫面多一個模式選擇「比賽（有對手）/ 計時賽」，或在開始按鈕旁加「計時賽」。開賽前同樣詢問自排或手排（沿用手排功能的對話框）。
2. **規則**：不建立 AI 對手、不計算對手碰撞，HUD 不顯示與對手的距離，改為與最佳紀錄的時間差。完賽畫面顯示時間、與最佳的差、甩尾分數，並標示是否為新紀錄。
3. **紀錄**：最佳時間存在 `yatouge-ta-best-<track>-<car>`。比賽模式原本的最佳時間 key 不動。
4. **幽靈車**：
   - 跑的時候以約每秒 10 筆的頻率記錄 `t, s, lat, h, vis`（或 `x, z, h`），經量化與壓縮後，跟最佳時間一起存起來。存在 IndexedDB 或 localStorage，每筆要有大小上限。
   - 刷新最佳時才覆寫。
   - 重播：用半透明（opacity 約 0.35）的同款車，依時間插值顯示，沒有碰撞，不寫入物理。
   - 設定中可以開關幽靈車（預設開）。
   - 純函式：錄製取樣、壓縮與解壓縮、依時間插值，都要有測試。
5. **相容**：手排、三種手機操作、鏡頭、遊戲中選單都要能用；認輸改為「放棄」並回到主畫面，不存紀錄。

## B. 觀戰（後做）
1. **大廳**：公開房間在比賽進行中仍然列出，顯示「比賽中・觀戰」與觀戰人數。私人房間不列出，也不能觀戰。
2. **加入**：觀戰者以 `role: 'spectator'` 加入房間。在 presence 中標示自己是觀戰者，不送車子狀態，不參與 ready 或 go，不計入 2 人上限。參賽端的 `chooseOpp` 與 `raceSync` 一律忽略觀戰者，現有的「第三人不能接管」規則照常有效。
3. **畫面**：
   - 觀戰者用插值顯示兩台車，沿用現有的遠端車輛插值。
   - 鏡頭可以切換：跟車 A、跟車 B、俯視全景，用按鈕或鍵盤 1／2／3 切換。
   - HUD 顯示雙方暱稱、差距（m）與名次，完賽後顯示雙方時間與勝負。
   - 觀戰者隨時可以離開，回到大廳。
4. **參賽者**：HUD 顯示「N 人觀戰中」（N 為有效觀戰者人數）。
5. **傳輸層**：claude.ai 的 room 與 Supabase 都要支援。Supabase 的 presence 有每 30 秒 5 次的限制，觀戰者只在加入時 track 一次。觀戰者的頻寬只有接收。
6. **安全**：沿用既有的驗證；觀戰者送來的任何車子或比賽狀態一律忽略；觀戰人數顯示上限 99。

## Exit Criteria
1. 從專案根目錄執行 `node --test` 全部通過，0 個失敗。純函式（幽靈錄製與插值、時間差、觀戰角色判斷、觀戰者被參賽邏輯忽略）先紅後綠。
2. 瀏覽器檢查（一次只開一個瀏覽器，開之前先檢查記憶體）：
   - 計時賽：沒有 AI，新紀錄會被儲存；第二次跑時看得到幽靈車，HUD 顯示與最佳的時間差。
   - 觀戰（用 mock 的兩個參賽分頁加一個觀戰分頁；必須在同一個瀏覽器的多個分頁內完成，不得開第二個瀏覽器）：大廳顯示「觀戰」；觀戰者看得到兩台車，可以切換視角；參賽者看到觀戰人數；私人房間不出現觀戰選項；觀戰者不影響比賽。
   - console 沒有錯誤。
3. 結束時關閉所有測試 server 與瀏覽器。
