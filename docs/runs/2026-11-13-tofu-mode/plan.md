# 送酒模式（原「豆腐模式」）— 實作計畫

> **更名（使用者 2026-11-13）**：為了避免直接連結到特定作品，「豆腐」一律改成「送酒」，配合 KX-2 車門的「夜峠酒舗」字樣。以下內文中的「豆腐模式」都改為 **「送酒模式 / Sake Run」**；過關訊息從「豆腐送達！」改為 **「酒送達！」**（英文 "Sake delivered!"）。杯中液體改成淡金色的清酒（不是水），視覺上是要送達的貨。物理與規則完全不變。存檔 key 改為 `yatouge-sake-best`，程式中的識別字用 `sake`。（使用者曾短暫考慮改成紅酒模式，最後決定維持送酒 / Sake。）程式與文案中都不出現「豆腐」、「とうふ」、「藤原」。

結論：新增「豆腐模式」挑戰。強制使用車內視角，開白色 KX-2（panda 配色），在青嵐峠下坡，沒有 AI。車內的杯架上放一杯水，水面會依 G 力即時晃動，撞牆時只會灑出一點點。碰牆三次就失敗，必須在 3:15 內抵達終點，否則也失敗。在手排變速箱、計時賽、觀戰之後實作，一次只跑一個 builder。

Pipeline：Frontend Feature SDD — Light Path。

## 使用者需求與決定（2026-11-13）
- 強制車內視角、白色 KX-2、第二條賽道（青嵐峠）。
- 車內有杯架與裝水的杯子；水依 G 力晃動；撞牆只灑出一點。
- 第 3 次碰牆就失敗（前兩次不失敗）。HUD 顯示剩餘次數，例如三個杯子圖示，每撞一次少一個。
- 任何碰到護欄都算一次，包括輕擦。
- 沒有 AI，只有時間限制；3:15 內抵達終點才算過關。保存最佳過關時間。開賽前仍然詢問自排或手排。

## 設計
1. **入口**：主畫面的模式選擇多一個「豆腐模式」，旁邊附一句說明。選擇後鎖定車型（KX-2，顏色 3 白）、賽道（seiran）與鏡頭（cockpit）。這些設定只在這個模式中強制，不覆寫玩家原本存的車、賽道與鏡頭選擇。比賽中不能切換鏡頭：C 鍵與鏡頭按鈕無效或隱藏。
2. **碰牆計數**：
   - 任何一個車角碰到護欄就算一次接觸（沿用碰撞系統的接觸判定）。
   - 一次連續的擦牆只算一次：接觸結束、離開牆面至少約 0.4 秒後的下一次接觸，才算新的一次。
   - 第 3 次立即失敗。計數規則寫成純函式並測試。
3. **計時**：
   - HUD 顯示倒數，從 3:15.00 開始。
   - 時間到還沒抵達終點就失敗；抵達終點時剩餘時間 > 0 就過關。
   - 最佳過關時間存在 `yatouge-tofu-best`，可以依手排或自排分開記錄，由 maker 決定。
4. **杯架與杯子**（加在車內模型中，位置在中控台附近、看得到的地方）：
   - 杯架是一個深色環形座；杯子是半透明的紙杯或玻璃杯；水是一個淡藍、半透明的圓盤或淺圓柱。
   - **晃動**：用彈簧阻尼模型（純函式）。輸入是車子的縱向與橫向加速度（G 力），輸出是水面的傾斜角與晃動量。煞車時水往前湧、轉彎時往外側、甩尾時明顯擺盪，平穩時逐漸停止。
   - 傾斜角有上限，約 25°，看起來自然、不誇張。
   - **灑水**：只有撞牆時才灑。依撞擊力道減少一點點水位（每次約 3–10%），並出現幾顆小水滴的短暫粒子動畫。平常再怎麼晃都不會灑。
   - HUD 上也可以顯示水位百分比，作為參考。水位不影響勝負。
5. **結果畫面**：
   - 過關：「豆腐送達！」，顯示用時、剩餘時間、碰牆次數、剩餘水位，並標示是否為新紀錄。
   - 失敗：分成「撞太多次了」與「超時」兩種原因。
   - 都提供「再挑戰」與「回主畫面」。
6. **相容**：手排、三種手機操作、遊戲中選單都要能用，其中「認輸」改為「放棄」。KX-2 的時速警示音、車門字樣設定照常有效。

## Exit Criteria
1. 從專案根目錄執行 `node --test` 全部通過，0 個失敗。下列純函式先紅後綠：
   - 碰牆計數，含連續擦牆只算一次、第 3 次失敗；
   - 倒數與勝負判斷；
   - 水面晃動的彈簧阻尼（有上限、會回穩、方向正確）；
   - 撞牆時灑水量的範圍。
2. 瀏覽器檢查（一次只開一個瀏覽器，開之前先檢查記憶體）：
   - 選豆腐模式後，強制車內視角、白色 KX-2、青嵐峠，沒有 AI；
   - 看得到杯子，煞車與轉彎時水面傾斜（截圖）；
   - 碰牆三次就失敗；
   - 超時就失敗；
   - 在時限內抵達終點會顯示過關並保存紀錄；
   - 不會覆寫玩家原本的車、賽道與鏡頭設定；
   - console 沒有錯誤。
3. 結束時關閉所有測試 server 與瀏覽器。
