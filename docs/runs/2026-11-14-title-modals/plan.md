# 主畫面設定改成彈出視窗、上下坡改在開始時選、線上上坡、聊天放右邊（2026-11-14）

結論：主畫面只留模式、賽道、三個設定按鈕（車輛設定、聲音設定、遊戲設定）與開始／線上按鈕，設定內容移到彈出視窗（modal）。上坡／下坡從主畫面移到按「開始」之後選（和 AT／MT 同樣樣式，在 AT／MT 之前）。線上對戰新增上坡：按「準備」後選方向，方向跟著投票一起抽籤。房間的聊天框在寬螢幕改放右側一欄，不用捲到下面。使用者不在，以下設計由我依建議方案決定，假設記在最後一節。

流程：Frontend Feature SDD。沒有 API（跳過第 1 步）；這個 repo 沒有 OpenSpec，規格寫在本檔（依專案慣例 `docs/runs/`）。設計關卡因使用者離開並明示「有問題先用你建議的」，由我代為簽核，記錄於下方「未解問題與假設」。

## 使用者的要求（原文重點）
1. 主頁的設定太亂，做成 modal：點「車輛設定」跳出車輛設定 modal；點「聲音設定」跳出聲音 modal，裡面有選擇 BGM、開關音樂等。
2. 上坡／下坡改為點開始遊戲後選，類似 AT／MT。
3. 線上對戰目前沒有上坡選項，一樣點「準備」再選。
4. 房間的聊天框放右邊，玩家不需要捲到下面才看得到。

## 規格

### 一、主畫面
- 保留：語言按鈕、標題、說明、模式選擇（含計時賽的幽靈車開關、送酒模式的鎖定說明）、賽道選擇、按鍵說明、開始與線上按鈕、操作提示。
- 移除主畫面上的：行駛方向選擇、車輛卡片與顏色、背景音樂列、KX-2 開關、震動、彎道提示、按鍵設定、更新內容、觸控操作設定。
- 新增一列三個按鈕：
  - **車輛設定**：按鈕上顯示目前的車名與顏色色塊（例如「KX-2 Hatch ●」），一眼看得出選了什麼。
  - **聲音設定**
  - **遊戲設定**
- 送酒模式強制 KX-2 白色時，車輛設定按鈕顯示強制的車，modal 內的車輛選擇維持原本送酒模式的鎖定行為。

### 二、車輛設定 modal
內容：車輛卡片（原 `#pick`）、顏色（原 `#swatches`）、KX-2 專屬開關（時速警示音、車門字樣、極速升級；只在 KX-2 時顯示，與原本相同）。
- 選車、選色的行為、存檔 key、鍵盤操作（方向鍵、Space、焦點保持）全部沿用原本的元件，只是搬到 modal 裡。
- 下方一個「完成」按鈕關閉。

### 三、聲音設定 modal
內容：背景音樂選擇（原創／自選，原 `#btnBgm`）、選擇音樂檔、移除、錯誤訊息（`#ownMsg`）、**音樂開關**（新的 switch，與比賽中按 M 鍵、遊戲內選單的音樂開關是同一個狀態）。
- 不改任何聲音本身（音色、音量、時機都不變）。

### 四、遊戲設定 modal
內容：震動、彎道提示、按鍵設定（開啟原本的按鍵設定頁）、更新內容（開啟原本的更新紀錄視窗）、觸控操作設定（原 `#tCtl`，只在觸控裝置顯示，與原本相同）。
- 從這個 modal 打開按鍵設定或更新內容時，關閉後回到遊戲設定 modal。

### 五、modal 共通行為
- 用同一套樣式（沿用遊戲內選單與變速箱視窗的 `.screen` + `.sheet` 風格），`role="dialog"`、`aria-modal="true"`、有標題。
- 開啟時主畫面 `inert`，焦點移到 modal 第一個控制項；Esc、點「完成」、點背景都會關閉；關閉後焦點回到打開它的按鈕。Tab 在 modal 內循環。
- modal 開著時，主畫面的 Enter 不會開始比賽；手把 B 鍵關閉 modal。
- 中英文都有，台灣用語。

### 六、上坡／下坡在開始時選
- 按「開始」（以及 Enter、手把開始）後先出現「選擇方向」視窗：「下坡」「上坡」兩個大按鈕，樣式與 AT／MT 視窗相同，有簡短說明；預設焦點在上次選的方向（沿用 `yatouge-dir`）。選完接著出現原本的 AT／MT 視窗，再開始比賽。取消方向視窗回到主畫面。
- 送酒模式只有下坡：不出現方向視窗，直接 AT／MT（與原本相同）。
- 結果畫面「同一台再跑」：沿用上一場的方向，不再問方向（只問 AT／MT，與原本相同）。遊戲內選單的「重新開始」也沿用。
- 主畫面上方的賽道說明（`#courseInfo`）、計時賽最佳成績等，顯示上次選的方向，與原本相同。

### 七、線上上坡（使用者後來補充的流程）
使用者原話：「pvp 的改成點選擇賽道時，跳出上坡下坡的 modal；選車時跳出 AT／MT modal；都選了才能按 ready」。
- 房間裡點賽道投票的某條賽道時，跳出同樣的「選擇方向」視窗；選了方向，這一票才成立（賽道＋方向）；取消就不改原本的投票。
- 點「你的車」選車時，跳出 AT／MT 視窗；選了變速箱才算選好車；取消就不換車。
- 兩者（這個房間裡的方向與變速箱）都選過，「準備」才可以按；沒選完時準備按鈕停用，並在旁邊提示還缺什麼。重新進房間時要重新選（變速箱的預設焦點沿用 `yatouge-trans`，方向沿用 `yatouge-dir`）。
- 因為變速箱已經在選車時選好，雙方準備、抽籤之後**不再跳出 AT／MT 視窗**：直接用選好的變速箱（自動送出 `gb`），抽籤結果（賽道、方向、模式）顯示在房間標題與提示文字，接著倒數。
- 方向是投票的一部分：投票內容 `{ t, m, g }` 加上 `d: 'down' | 'up'`。主機抽到哪一票，就用那一票的賽道與方向（兩票相同就直接用）。抽籤結果的文字顯示方向（例如「黑鷺山 · 上坡」）。
- 對戰、貓捉老鼠、觀戰都要用抽到的方向建賽道；觀戰者跟著主機的方向。
- 協定版本 `RP.V` 從 3 改為 4（投票格式改變），舊版頁面互相看不到房間，需要重新整理。

### 八、房間聊天放右邊
- 寬螢幕（目前房間有雙欄排版的寬度以上）：房間改成三欄或「左：投票與玩家、右：聊天」的排版，聊天框占右側一欄，高度跟房間內容一樣高，訊息區自己捲動，輸入框固定在聊天欄底部，一進房間就看得到，不用捲動頁面。
- 窄螢幕（手機）：維持在玩家列與準備按鈕下方，但訊息區高度限制在可視範圍內，輸入框不需要捲很遠才看到。
- 聊天功能本身不變。

## 不變
手感、物理、AI、車輛模型、聲音的音色與時機、計時賽與送酒模式的規則、存檔 key（`yatouge-car`、`yatouge-dir`、`yatouge-trans` 等）、簽章與送出頻率、presence 次數。

### 各任務
1. **modal 共通機制**：新增 `@title-modals` 純函式區塊（`focusStep` 焦點循環索引、`carSummary`、`startAsksDir`、`rpReadyOk`、`rpMissing`）。`enterStartsRace(el, blocked)` 加上 blocked 參數，Enter 處理行傳入 `tmOpen !== null || dirOpen`。`tmOpenModal`／`tmClose`／`tmKeydown` 處理 inert、第一個控制項取得焦點、Esc、Tab 循環、關閉後焦點回到按鈕、點背景關閉；M 鍵在 modal 內與遊戲內選單一樣可切換音樂。手把 B 走 `gpBack`，`gpScope`／`gpCtx` 都認得 modal 與方向視窗。按鍵設定頁與更新內容視窗從「遊戲設定」打開時，關閉後 modal 還在、主畫面仍 inert。測試：焦點循環、Enter 被擋、開／關／Esc／Tab 的假 DOM 測試、gpBack、kb／cl 關閉後的 inert 狀態。
2. **主畫面改版與三個 modal**：主畫面只留模式、賽道、三個設定按鈕、按鍵說明、開始／線上。`#pick`、`#swatches`、`#tKx` 搬到 `#mCar`；`#btnBgm`、`#btnPick`、`#btnOwnClear`、`#ownFile`、`#ownMsg` 搬到 `#mSnd`；震動、彎道提示、按鍵設定、更新內容、`#tCtl` 搬到 `#mGame`，id 全部不變。車輛設定按鈕用 `carSummary` 顯示車名、顏色與色塊（`syncCarBtn`，在 `renderPicker` 尾端呼叫，送酒模式顯示被強制的車）。測試：id 位置、`role="dialog"` 屬性、`carSummary`（含壞索引）。
3. **音樂開關**：`#tMusic`（`syncMusicSw`）由 `setMusic` 與 `ownRelabel` 同步，所以 M 鍵、手把、遊戲內選單都會更新它。測試：`setMusic` 後開關狀態、點擊接線。
4. **方向視窗**：新增 `#dirq`（樣式沿用 `.transbtn`）、`askDir`／`dirPick`／`dirCancel`；`askStart` 依 `startAsksDir` 決定「方向 → AT／MT」或直接 AT／MT。開始鈕、Enter、結果畫面「同一台再跑」（`again = true`）都改走 `askStart`；遊戲內選單的重新開始本來就直接 `startRace`，沒有變。開始鈕文字改成不含方向的「開始」／「Start」。移除主畫面的 `renderDirPicker` 與 `#dirPick`。測試：askDir 的 inert、預設焦點、取消、不重複開；askStart 三種情況。
5. **線上**：`RP.V = 4`、`RP.DIRS`；`validVote` 要有 `d`；`resolveVote` 把賽道與方向當成同一張票（相同直接用，不同整張抽，結果多一個 `d`，`dt` 表示賽道與方向有抽籤）；`pickSig` 含方向；`netTrack` 讓 `trk` 可以是 `<id>_up`（`NET.TRACKS` 不變，大廳廣告用 `baseId(p.track)`）；`rpMatchText`／`rpVoteText` 顯示方向；抽籤後 `p.track` 是實際課程 id，比賽、貓捉老鼠、觀戰都跟著用；觀戰者靠既有的 `specTrackSwitch` 跟著主機的 `trk`。房間裡點賽道先問方向、點車先問 AT／MT（`rpPickTrack`／`rpPickCar`，取消不改票、不換車），`p.dirOk`／`p.gbOk` 每個新房間都是 false，兩個都為真且有對手才能準備（`rpReadyOk`），缺什麼顯示在 `#rpNeed`。`rpStep` 在抽籤完成後直接送出 `gb`，不再跳 AT／MT 視窗（移除 `asking` 與 `#transMatch`）；抽籤結果顯示在房間標題與提示文字。測試：validVote、resolveVote（同 seed 同結果、方向不拆票）、pickSig、validatePeerState、rpMatchText、rpResolve、rpPickTrack、rpPickCar、rpStep、準備按鈕接線。
6. **房間聊天**：`#roomChat` 移出 `.rside` 成為 `.roomsheet` 的直接子元素；`min-width: 900px` 且 `min-height: 501px` 時房間變三欄，聊天占右欄、與房間內容同高、訊息區自己捲動、輸入框在欄底；短橫向手機的雙欄版型多一列放聊天；直向手機維持在準備按鈕下方，訊息區縮短為 `min(100px, 14vh)`。純 CSS，只有結構測試，沒有看過畫面。
7. **更新紀錄**：2026-11-14 加入四條玩家向說明（三個設定視窗、開始時選方向、線上上坡、聊天放右邊），中英各四條，英文不以 `Fix:` 開頭，中英條數相同。測試：內容與條數。
