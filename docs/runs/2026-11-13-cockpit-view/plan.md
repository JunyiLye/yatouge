# 車內視角：手機倒後鏡與儀表高度（2026-11-13）

結論：手機橫放時，車內視角的倒後鏡縮小到不超過畫面高度的一半寬；KX-2 與 GT-32 的儀表群往下移，和 SR-7 一樣比眼睛低 0.28 m，不再擋住前方視野。

## 使用者回饋
- 手機玩第一人稱時，倒後鏡太大，擋住前面的視野，希望做 RWD。
- KX-2（AE86 風格）與 GT-32（R32 風格）的儀表盤太高，有點擋視野。

## 原因
- `layoutMirror` 只依畫面寬度決定鏡子寬度（`clamp(w × 0.38, 150, 380)`）。844×390 的手機上鏡子約 320×100，佔掉上方約三成。
- KX-2 與 GT-32 沒有覆寫 `clusterY`，儀表群在儀表板頂面上方 3 cm（0.93 m、0.91 m），錶罩頂端接近眼睛高度；GT-32 的錶罩甚至高過路面地平線。SR-7 早已用 `clusterY: 0.72` 壓低。

## 決定
- 新增純函式 `mirrorWidth(w, h) = clamp(min(w × 0.38, h × 0.5), 150, 380)`，放在 `@camera-modes` 區塊，由 `layoutMirror` 使用。高度 760 px 以上的桌機維持 380，不變；高度不到 760 px 的視窗會略小，例如 1280×720 是 360。
- `COCKPIT_CARS.hatch.clusterY = 0.84`、`COCKPIT_CARS.gtr.clusterY = 0.78`（都比眼睛低 0.28 m，與 SR-7 相同）。眼睛、方向盤、儀表板頂面、SR-7、GT-32 的三個小錶都不動。

## Exit Criteria
- 新增的 `mirrorWidth` 與 `clusterY` 測試先失敗、實作後通過；從專案根目錄執行 `node --test` 全部通過。
- 手機（844×390）與桌機（1366×768）三台車的車內視角，修改前後照片並排比對：手機倒後鏡變小，KX-2 與 GT-32 看得到引擎蓋與前方道路，桌機倒後鏡大小不變。
- 換行只有 LF、沒有 `__lc`、沒有隱形字元，script 可以解析。
- 需要使用者在手機上試玩確認。

## 驗證紀錄
- `node --test`：468 個全部通過。
- 照片：`before/` 與 `after/`（不進 git）。手機倒後鏡約 330×110 → 約 205×70；GT-32 錶罩降到地平線以下；KX-2 看得到引擎蓋；SR-7 儀表不變；桌機倒後鏡維持 380 寬。
- 截圖腳本 `shots.cjs`（不進 git）：一次啟動一個 headless 瀏覽器，拍完即關閉，結束後 `chrome-headless-shell.exe` 數量為 0。

## Review 與處置
- 獨立 code review：沒有嚴重或重要問題。
- KX-2 錶罩頂端仍比擋風玻璃下緣視線高約 5.5 cm（GT-32 貼齊）。使用者決定先維持 0.84 推上去試玩，覺得擋再降到約 0.80，並加上三台車錶罩不高過視線的測試。
- 改寫的既有斷言（預設儀表群在儀表板頂面上方）保留原本對預設公式的保護，接受。
