# 深度檢查 D：音效、HUD、鏡頭、比賽流程（yatouge.html 3458–4676，main 7d36d13）

## D1（中）關掉「車門字樣」後，玩家自己的 KX-2 仍顯示字樣
- 位置：`yatouge.html:4273`（`syncBody`）；字樣 mesh 在 2905 建立。
- 原因：`syncBody` 把車身群組所有直接子物件設成 `o.visible = !hide`，只排除車頭燈、燈光目標與車內模型；車門字樣也是直接子物件，被改回顯示。觸發時機：載入後第一幀、每次 `buildCars()`（換車、換色、換賽道、換方向、換模式）、從車內視角切回、回主畫面。
- 重現：選 KX-2，主畫面關掉車門字樣，重新整理或換一次顏色，主畫面與追尾視角仍看得到字樣（對手車與幽靈車正確隱藏）。Node 執行 `syncBody` 原始碼：第一幀前 false、第一幀後 true。
- 預期：顯示車身時字樣跟著 `kxLetterOn`。
- 信心：高。

## D2（低到中）`fmtT` 進位時顯示「0:60.00」或「0:010.00」
- 位置：`yatouge.html:3742`。
- 原因：先判斷 `s < 10` 再 `toFixed(2)`，沒處理進位。用在 HUD 計時、結果畫面、最佳時間、計時賽卡片、送酒倒數。
- 重現（node）：59.996 → 0:60.00；119.997 → 1:60.00；9.996 → 0:010.00；69.999 → 1:010.00。
- 預期：先四捨五入到 0.01 秒再拆分與秒。
- 信心：高。

## D3（低）回到主畫面後，鏡頭 FOV 停在上一場的值
- 位置：`yatouge.html:4308-4314`（主畫面鏡頭分支）；4299-4302 的 `easeFov` 是唯一寫入 `camera.fov` 的地方。
- 原因：主畫面環繞鏡頭不呼叫 `easeFov`，沿用最後一幀的 FOV（車內或送酒結束後 76–84°，直向手機最高 95°）。
- 重現：用車內視角跑完一場或跑一次送酒，按回主畫面，主畫面的車比剛載入時明顯變小。
- 預期：主畫面固定一個 FOV（例如 66°）。
- 信心：高（只影響畫面）。

## D4（低）再點一次已選的車卡，顏色重設成第一色並存檔
- 位置：`yatouge.html:4542`。
- 原因：車卡 click 一律 `choice = { car: k, color: 0 }; chosen();`，沒檢查是否同一台車。
- 重現：選 KX-2 深藍，再點一次 KX-2 卡片，顏色變回紅黑雙色，重新整理後仍是紅黑雙色。
- 預期：點已選的車不做任何事。
- 信心：中（不能完全排除是刻意設計）。

## 檢查過、沒發現問題
音效節點不累積；自選音樂的 object URL、失敗退回、IndexedDB 不可用、分頁隱藏都有處理；紀錄依賽道、方向、車、KX-2 升級分開（送酒最佳共用是既定決定）；結果畫面標籤還原；幽靈車與清酒杯在各種路徑都會釋放；送酒模式擋下選車、選色、選賽道、選方向；鏡頭的 view offset、roll、車內加速度狀態都有重設。
