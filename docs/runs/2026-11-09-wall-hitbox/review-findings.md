# Code Review Findings — 精確碰撞框與撞牆機制

結論：沒有 Critical。衝量計算、摩擦補正和 SAT 都正確。審查者用 15 萬次隨機撞擊驗證過，能量不會增加。但有一個真實的手感問題：幾乎正面撞牆時，車子會以約 5 rad/s 往隨機方向打轉，正好發生在使用者在意的高速撞牆情境。處置等使用者決定。

審查者：fresh-context code-reviewer subagent（唯讀，沒有開瀏覽器）。`node --test` 66/66。

## CR1 — 正面撞牆時隨機打轉（Important）
- 位置：`yatouge.html` 約 513–521 行（`wallContact`）
- 說明：車頭正對護欄時，兩個前角一樣深，但程式只取其中一個角作為接觸點，由浮點誤差決定是哪一個。結果以 25 m/s 正面撞牆時，車子會以約 5 rad/s 往隨機方向打轉；偏差 ±0.001 rad，方向就相反。真實情況下兩角同時接觸，幾乎不會轉。車與車碰撞已經會平均相近的角，撞牆卻沒有，兩者不一致。另外，撞擊後的角速度沒有上限：撞牆約 5 rad/s，車與車撞後角最多約 10 rad/s。
- 建議修法：撞牆時平均深度相差 2 cm 以內的角，補一個「正面撞牆 |w| ≈ 0 且左右對稱」的回歸測試。可選擇是否把撞擊後的角速度上限設在 3–4 rad/s。
- Disposition: pending

## CR2 — 打轉中的車尾擦牆也可能被罰（Important，需要使用者決定）
- 位置：`wallImpulse` 的 `vn`，`wallPenalty` 約 1077 行
- 說明：撞擊速度包含車身旋轉。車子以 ±2 rad/s 打轉時，即使整車移動很慢，車尾（離車心約 2.4 m）擦到牆的速度也可能超過 5 m/s，會被罰 0.8 秒並跳提示。這是依照計畫的定義，但使用者的本意是「甩尾擦牆後反打方向不受罰」。
- 選項：(a) 維持現狀；(b) 懲罰只看整車往牆的速度，不含旋轉。反彈仍然用接觸點的速度計算。
- Disposition: pending

## CR3 — `physics()` 的接線沒有 node 測試（Important）
- 說明：對手車的 s、lat 換算、`T('wallPen', secs)` 的呼叫、衝量結果寫回 `c` 這幾段只由瀏覽器驗證涵蓋。
