# 手機傾斜轉向與單指操作模式 — 實作計畫

結論：在遊戲內選單的設定中，新增「轉向方式」選項：
- 拖曳（現有的左手類比轉向區）；
- 傾斜（新增）：用手機左右傾斜來轉向，油門自動，觸碰螢幕就煞車並踢一下手煞車，持續按住就持續煞車，放開恢復油門。

預設是拖曳。鍵盤操作與拖曳模式完全不變。

Pipeline：Frontend Feature SDD — Light Path（單一檔案、無 API、無新相依；感測器只在使用者開啟時才請求權限）。

## 使用者決定（2026-11-12）
- 傾斜轉向作為設定中的第二種轉向方式。
- 傾斜模式的操作由使用者自行設計：油門一律自動；碰到螢幕就煞車加手煞車並鬆油門；按住就是不給油、持續煞車；放開恢復油門。

## 追加：第三種操作「分區」（使用者 2026-11-12）

使用者畫出的畫面配置：上方分成左右兩半，左半邊是左轉、右半邊是右轉；下方整排是煞車加手煞車。

規則照傾斜模式（使用者已確認）：
- 油門自動。
- 按住左半或右半，就往該方向打滿，平滑程度與鍵盤相同；左右同時按住時不轉向。
- 下方區域約佔畫面高度 30%，使用與傾斜模式相同的踏板狀態機：輕點是煞車加約 0.25 秒的手煞車，按住是持續煞車，放開恢復油門。
- 多指可以同時操作；手指從一區滑到另一區時，依目前所在的區域判定。
- 設定值為 `yatouge-steer-mode = zones`。預設仍是拖曳。

## 設計
1. **設定**：
   - 遊戲內選單的設定中新增「轉向方式：拖曳／傾斜」，以及「傾斜靈敏度」滑桿。
   - 兩者都存在 `store`（`yatouge-steer-mode`、`yatouge-tilt-sens`）。只在觸控裝置顯示。
   - 切換到傾斜時，若需要（iOS 的 `DeviceOrientationEvent.requestPermission`），在這次點擊中請求權限。
   - 被拒絕或沒有感測器時，退回拖曳模式，並顯示「此環境無法使用傾斜轉向」（例如 claude.ai 的內嵌框架可能拿不到感測器）。
2. **傾斜轉向**：
   - 讀取 `deviceorientation`，依 `screen.orientation.angle`（90 或 −90/270）決定使用哪一軸與正負號，讓「把手機當方向盤往右轉」等於向右。
   - 校正：開始倒數時，以當下的角度作為中心。另有「回正」按鈕可重新校正。
   - 對應：`steer = clamp((angle − center) / maxAngle, −1, 1)`，加上小死區後重新縮放；`maxAngle` 依靈敏度約為 12° 到 35°。
   - 平滑化以去除抖動。結果寫入 `input.steerAxis`，沿用現有的類比轉向路徑。
3. **單指踏板（只在傾斜模式）**：
   - 沒有觸碰：油門開。
   - 觸碰開始：油門關、煞車開、手煞車開，持續約 0.25 秒（踢一下），之後手煞車關。
   - 持續按住：油門關、煞車開。
   - 放開：恢復油門，煞車關。
   - 多指觸碰視為同一個「按住」。整個畫面（扣除 HUD 按鈕、☰、回正鈕）都是觸碰區。
   - 隱藏拖曳轉向區與原本的踏板按鈕。
   - 倒數期間不自動給油，比賽開始才給。
   - 選單開啟、視窗失焦或比賽結束時，所有輸入歸零。
4. 狀態判斷與數學都寫成純函式，放在標記區塊：踏板狀態機（輸入 touching 與按下後經過的時間）、角度到轉向的對應、軸與正負號的選擇。

## Exit Criteria
1. 從專案根目錄執行 `node --test` 全部通過，0 個失敗。純函式的測試要先紅後綠：
   - 踏板狀態機：未觸碰、輕點、按住、放開；
   - 傾斜對應：死區、上限、靈敏度；
   - 依螢幕角度選擇軸與正負號，涵蓋 90 與 −90 兩個方向。
2. Playwright 手機模擬（landscape 844×390），用 stub 送出 `deviceorientation` 事件：
   - 傾斜模式下，傾斜改變 `steerAxis` 與車子方向；
   - 不觸碰時自動加速；
   - 輕點會觸發手煞車；配合轉向可以甩尾；
   - 按住會減速；放開恢復加速；
   - 回正按鈕有效；
   - 權限被拒或沒有感測器時，退回拖曳模式並顯示提示；
   - 拖曳模式與鍵盤操作不變；
   - console 沒有錯誤。
3. 結束時關閉所有測試 server 與瀏覽器。
